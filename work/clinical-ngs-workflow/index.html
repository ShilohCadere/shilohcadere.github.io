Clinical NGS Workflow

A Nextflow DSL2 demonstration workflow connecting paired-end FASTQ inputs to QC, alignment, sorted BAMs, variant calling, and a lightweight VCF summary.

Make the dependencies explicit.

A reproducible sequencing workflow needs more than a sequence of shell commands. Inputs, references, process outputs, and execution order must remain visible so the workflow can be configured and inspected.

What I built

  • Read paired-end samples from a CSV samplesheet.
  • Run FastQC, BWA-MEM alignment, BAM sorting and indexing, and bcftools variant calling.
  • Generate a lightweight per-sample VCF summary and aggregate FastQC results with MultiQC.
  • Provide configurable paths and a Docker-based execution profile.
Evidence in the repository

What can be inspected.

The main workflow and modules expose the dataflow; the Dockerfile and Nextflow configuration define the execution environment and configurable paths.

Implementation choices.

Modular DSL2 processes

QC, alignment, sorting, calling, and summarization remain separate modules with explicit inputs and outputs.

Track data, not published folders

MultiQC receives the FastQC output channel directly, allowing Nextflow to track that dependency.

Separate configuration and orchestration

The samplesheet, reference, output directory, and execution profile are set outside the main workflow logic.

Scope & limitations

Where the evidence stops.

A portfolio demonstration, not a clinically validated pipeline. The repository documents that integration tests, CI execution checks, and detailed executor/resource tuning are not yet implemented.

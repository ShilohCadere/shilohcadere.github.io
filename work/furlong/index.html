Furlong

A working travel-planning application built with Flask and SQLite. The technical focus is on persistent user data, comparing alternatives, and keeping temporary exploration separate from saved decisions.

PythonFlaskSQLiteHTML / CSS / JavaScript
Implementation

Flask application with server-rendered templates

Project stage

In development · Source currently private

Example data

Seeded Europe 2027 trip

Keep alternatives without losing the plan.

Trip planning involves competing stays, changing quotes, different route lengths, and choices that affect several parts of a budget. Furlong keeps those possibilities connected to a trip and its scenarios.

What I built

  • Username-based registration and login, with trips associated with their owner.
  • Persistent trip records, dated itinerary days, and editable activities.
  • Saved stays, quotes, dates, links, and notes, with separate choices for each route scenario.
  • City notebooks connecting selected accommodation, local ideas, and itinerary entries.
  • A temporary Budget Playground and a separate current-plan expense ledger.

Development status

Furlong is an actively developed Flask and SQLite travel-planning application. The functionality described here is implemented on the feature/saved-options-panel development branch. The default main branch currently represents an earlier development milestone.

The screenshots show the development interface using example trip data. The application has not been publicly released, and production deployment and security validation remain future work.

Implementation choices.

Persistent data belongs to an account.

SQLite stores the application records, with ownership checks restricting trip access to the signed-in user. The implementation uses Werkzeug password hashing and Flask sessions.

Scenario choices stay separate.

Alternative routes hold their own selections and budget settings. Options can be considered without flattening all possibilities into a single trip total.

Exploration stays temporary.

The Budget Playground recalculates hypothetical changes in the browser. It leaves saved selections and recorded expenses unchanged, so trying a possibility does not silently commit it.

Scope & limitations

A working development build.

The current implementation is being refined through real trip planning. Source access remains private, and no public application is linked from this portfolio.

Production readiness, a public release, and security validation are separate from the demonstrated implementation.

Furlong is a Cadere Productions product. This case study focuses on the technical implementation; its studio showcase covers the product experience.

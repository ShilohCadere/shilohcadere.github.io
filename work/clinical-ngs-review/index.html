Bioinformatics / QC review

Clinical NGS Review

An analyst-focused Python system for reviewing sequencing metrics after pipeline execution. It separates input validation, configurable QC logic, and reporting so each responsibility can be understood and tested.

View repository ↗
Implementation

Python · pandas · PyYAML · pytest

Project stage

Portfolio implementation

Data context

Simulated sequencing metrics

QC metrics need an interpretation layer.

A list of sequencing metrics does not explain which samples require attention or whether the same issue is recurring across a run. This project models the review layer between pipeline execution and an analyst’s next investigation.

What I built

  • Load metrics and sample metadata, checking required columns before analysis.
  • Apply YAML-configured minimum and maximum rules to generate PASS, FLAG, and FAIL classifications.
  • Represent findings as structured data with evidence, priorities, and recommended review actions.
  • Identify recurring run-level patterns and produce CSV summaries and Markdown reports.
Evidence in the repository

What can be inspected.

The repository includes unit tests and a GitHub Actions workflow that runs pytest on pushes and pull requests to main. The configuration and analytical implementation are available for inspection.

Implementation choices.

Configuration outside the code

Review thresholds live in YAML, so criteria can change without rewriting the analysis.

Structured findings before formatting

The analysis produces reusable findings; CSV and Markdown are reporting views of the same result.

Test responsibilities independently

Ingestion, classification, run summarization, reporting, and CLI configuration have separate tests.

Scope & limitations

Where the evidence stops.

Uses simulated sequencing data and non-clinical demonstration thresholds. It is not a clinical interpretation system. Direct integration with Clinical NGS Workflow remains future work.
